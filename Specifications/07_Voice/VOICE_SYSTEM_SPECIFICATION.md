# JARVIS-X Voice System Specification

**Document Version:** 1.0.0-draft  
**Last Updated:** 2026-07-23  
**Status:** Active Draft  
**Target System:** JARVIS-X Voice Processing & Speech Subsystem  

---

## 1. Purpose
The Voice System is the primary real-time auditory interface of JARVIS-X. Inspired by the natural, fluid voice interactions of Iron Man's JARVIS, this subsystem enables hands-free voice control, continuous speech recognition (STT), low-latency wake word detection, neural speech synthesis (TTS), and intelligent conversational stream management across the desktop environment.

---

## 2. Vision
To create a voice-first computing experience where users interact with their operating system, files, and applications using natural conversational speech. The Voice System operates as a low-latency, ambient listening interface that understands natural phrasing, allows real-time user interruptions (barge-in), and responds with human-quality vocal feedback without compromising local privacy.

---

## 3. Design Principles
*   **Natural Interaction:** Supports fluid conversational phrasing, pauses, follow-up questions, and real-time user interruptions.
*   **Low Latency:** End-to-end voice loop (Speech-in to Speech-out) executes within < 800ms for local models.
*   **Offline First:** Core wake word detection, Voice Activity Detection (VAD), and fallback speech-to-text operate 100% locally without cloud dependencies.
*   **Modular Architecture:** Audio capture, transcription, synthesis, and playback are isolated behind clean event interfaces.
*   **Privacy-First:** Audio streams are processed in transient memory buffers and are never stored on disk or transmitted without explicit user consent.
*   **Extensibility:** Pluggable engine architecture allowing easy integration of third-party STT/TTS models (e.g., Whisper, ElevenLabs, Coqui).
*   **High Accuracy:** Advanced noise suppression, echo cancellation, and acoustic filtering ensure high transcription precision in noisy environments.
*   **Accessibility:** Fully accessible for users requiring complete hands-free navigation and auditory feedback.

---

## 4. Voice System Responsibilities
1.  **Wake Word Detection:** Continuously monitoring background audio for trigger phrases (e.g., "Hey JARVIS") with near-zero CPU footprint.
2.  **Voice Activity Detection (VAD):** Distinguishing human speech from ambient background noise and detecting silence boundaries.
3.  **Noise Suppression & Filtering:** Removing background noise, room reverb, and acoustic feedback from system speakers.
4.  **Speech-to-Text (STT):** Converting speech audio chunks into punctuated, formatted text strings in real time.
5.  **Intent Dispatching:** Forwarding transcribed text payloads to the AI Brain via the central Event Bus.
6.  **Speech Synthesis (TTS):** Converting text streams generated by the AI Brain into natural neural audio waveforms.
7.  **Audio Playback Management:** Controlling system speaker output, managing volume ducking, and handling immediate user interruptions (barge-in).
8.  **Session Lifecycle Management:** Managing active voice turns, timeout thresholds, and follow-up listening windows.

---

## 5. High-Level Voice Architecture

The real-time voice processing pipeline operates across five sequential stages:

```
[ User Speech (Microphone) ]
              |
              v
   [ 1. Microphone Manager ] ---> (Noise Suppression / Echo Cancellation)
              |
              v
   [ 2. Wake Word Detector ] ---> (Trigger Phrase Validation: "Hey JARVIS")
              |
              v
 [ 3. Voice Activity Detector ] -> (Speech Frame Segmentation)
              |
              v
     [ 4. STT Engine ] ---------> (Local Whisper / Streaming API)
              |
              v
       [ AI Brain Engine ] -----> (Intent Parsing & Response Assembly)
              |
              v
     [ 5. TTS Engine ] ---------> (Neural Voice Waveform Synthesis)
              |
              v
[ Audio Playback Manager ] -----> (System Speakers with Volume Ducking)
```

## 6. Core Components

### 6.1 Wake Word Engine
Low-power background audio classifier (e.g., Porcupine / OpenWakeWord) executing continuous sliding-window inference on incoming microphone buffers.

### 6.2 Microphone Manager
Interfaces with host OS audio subsystems (PortAudio / WASAPI / CoreAudio) to capture raw PCM audio streams (`16kHz`, `16-bit mono`).

### 6.3 Audio Recorder
Buffers transient audio frames during active speech sessions, feeding chunked bytes to the STT engine.

### 6.4 Voice Activity Detector (VAD)
Uses deep learning models (e.g., Silero VAD) to calculate speech probability scores per frame, triggering start-of-speech and end-of-speech events.

### 6.5 Speech-to-Text (STT) Engine
Transforms active speech frames into text using streaming local Whisper models or high-throughput cloud streaming APIs.

### 6.6 Text-to-Speech (TTS) Engine
Synthesizes streaming text tokens into expressive neural voice audio streams (e.g., Piper TTS, ElevenLabs, Edge-TTS).

### 6.7 Voice Session Manager
Manages state transitions: `IDLE_LISTENING` -> `WAKE_DETECTED` -> `RECORDING` -> `PROCESSING` -> `SPEAKING` -> `FOLLOW_UP_WAIT`.

### 6.8 Audio Playback Manager
Outputs audio streams through system speakers, automatically lowering background system audio (ducking) during voice responses.

## 7. Wake Word Detection
*   **Continuous Background Listening:** Operates in a low-power background thread consuming < 1% CPU.
*   **Supported Triggers:** Default wake phrase "Hey JARVIS" or customizable user phrases.
*   **Sensitivity Configuration:** User-adjustable threshold slider (`0.0` to `1.0`) balancing sensitivity against false positives.
*   **False Positive Prevention:** Requires two consecutive positive model frames before firing the `voice.wakeword.detected` event.
*   **Low Power Mode:** Suspends background inference when the host machine enters battery saver or sleep states.

---

## 8. Speech Recognition (STT)
*   **Real-Time Streaming:** Transcribes audio chunks progressively, rendering live text streams in the UI HUD overlay.
*   **Offline Engine:** Includes a bundled local Whisper (`base.en` / `small.en`) engine running via ONNX runtime for offline execution.
*   **Language Support:** Multi-language auto-detection with primary optimization for English.
*   **Automatic Punctuation:** Formats output text with proper capitalization, periods, and question marks before dispatching to the AI Brain.

---

## 9. Speech Synthesis (TTS)
*   **Natural Voice Profiles:** Ships with high-quality neural voice models trained for clear, professional assistant responses.
*   **Prosody Controls:** User-configurable controls for speaking rate (`0.8x` to `1.5x`), pitch adjustments, and volume levels.
*   **Streaming Synthesis:** Begins audio playback on the first sentence completion rather than waiting for the entire LLM response to complete.
*   **Emotion & Tone Adaptation:** Adjusts pitch and cadence dynamically based on response intent (e.g., urgent warning vs. standard information).

## 10. Voice Conversation Flow

```
+-----------------------------------------------------------------------------------+
| VOICE CONVERSATION STATE MACHINE                                                  |
|                                                                                   |
|  [ IDLE LISTENING ] --(Wake Word / Hotkey)--> [ WAKE DETECTED ]                   |
|           ^                                          |                            |
|           |                                          v                            |
|     (Timeout 5s)                             [ LISTENING (VAD) ]                  |
|           |                                          |                            |
|     [ FOLLOW-UP WAIT ] <--(Audio Complete)-- [ SPEAKING (TTS) ]                   |
|           |                                          |                            |
|           +----------------(Barge-in Interrupt)------+                            |
+-----------------------------------------------------------------------------------+
```

*   **Interruption Handling (Barge-In):** If the user begins speaking while the TTS engine is outputting audio, the VAD immediately cancels audio playback and transitions back to `LISTENING` mode.
*   **Follow-Up Window:** After finishing a response, the system remains in a low-sensitivity `FOLLOW-UP WAIT` state for 5 seconds, allowing hands-free follow-up questions without repeating the wake word.

---

## 11. Audio Management
*   **Hardware Selection:** Configurable input (microphone) and output (speaker/headset) device targets via UI settings.
*   **Noise Suppression:** Integrated Speex / WebRTC noise suppression filtering static hums and fan noise.
*   **Acoustic Echo Cancellation (AEC):** Prevents the system's own speaker output from re-entering the microphone input during speech playback.
*   **Audio Routing:** Automatically redirects audio streams when Bluetooth headsets or USB microphones are attached or disconnected.

---

## 12. Performance Optimization
*   **Audio Frame Ring Buffers:** Zero-copy circular memory buffers for streaming audio raw bytes.
*   **Quantized Model Inference:** Quantized INT8 model weights for STT/TTS engines, cutting RAM usage by 60%.
*   **First-Sentence TTS Chunking:** Splits text streams at sentence boundaries (`.`, `!`, `?`), feeding initial audio buffers to speakers within < 300ms of generation.

---

## 13. Privacy & Security
*   **Local Audio Sandbox:** Microphone streams are held exclusively in RAM ring buffers. No raw audio recordings are written to disk unless explicitly initiated by a user "Record Session" command.
*   **Permission Indicators:** Visual LED indicators in the UI overlay illuminate bright cyan whenever the microphone pipeline is actively streaming text.
*   **Mute Controls:** Hardware and hotkey toggle (`Ctrl+Shift+M`) to completely disable microphone access at the system driver level.

---

## 14. Error Handling & Resilience
*   **Microphone Disconnect:** Automatically pauses the voice engine, notifies the user via UI toast, and attempts auto-reconnection every 3 seconds.
*   **STT Engine Failure:** Falls back to secondary online/offline STT engines if the primary process times out.
*   **TTS Output Failure:** Displays text output in the HUD overlay if audio playback devices are unavailable or muted.

## 16. Testing Strategy
*   **Unit Tests:** Test VAD frame calculations, audio buffer allocation, and speech text formatting routines.
*   **Audio Mock Tests:** Feed pre-recorded synthetic WAV files into the microphone pipeline to test wake word detection rates and STT accuracy (Word Error Rate - WER).
*   **Latency Benchmarks:** Measure time elapsed between VAD end-of-speech detection and first TTS audio frame playback (Target: < 800ms).
*   **Barge-In Tests:** Verify immediate audio playback cancellation when user speech interrupts active TTS output.

## 17. Acceptance Criteria
*   [ ] Wake word detector achieves > 95% detection accuracy with < 1 false positive per 24 hours of idle listening.
*   [ ] End-to-end voice latency (End of user speech to start of TTS audio) is < 800ms on standard hardware.
*   [ ] Barge-in feature halts TTS audio playback within < 150ms of user speech interruption.
*   [ ] Mute hotkey reliably cuts microphone stream input at the audio driver layer.
*   [ ] Zero raw audio recording files are persisted to disk during normal operations.
